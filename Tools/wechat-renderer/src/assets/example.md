# 固定风格，让内容保持自己的声音

写作完成之后，排版应该是一道可靠的工序。文字、顺序和观点已经确定，接下来只需要让它们清楚地呈现在读者面前。

这是**普通粗体**，它保持近黑色；这是一句*轻一点的补充说明*，使用暖灰斜体。两者都不会被自动改成红色高亮。

## 先确定规则，再处理文章

<u>固定模板</u>把字号、行距和颜色写成明确规则。==同样的文章与模板，得到同样的排版。==

<mark data-tone="warning">只有原文明确标注的提醒，才出现浅黄色底条。</mark> Agent 负责执行，不替作者挑选重点。

### 章节与留白

二级标题与正文左对齐，通过字号、字重和留白分隔章节。段落保持 14px 字号、1.85 行高和 0.3px 字距。

![图床图片示例：腾讯云 COS 直链。](https://image-1325800846.cos.ap-nanjing.myqcloud.com/20260828134807607.png)

> 好的排版让文字更容易被读到。
>
> 它也应该让作者知道，每次生成的结果为什么是这样。

## 让操作可以重复

1. 保存原始 Markdown。
2. 调用固定模板。
   - 检查正文顺序。
   - 检查图片和代码。
3. 预览并复制到公众号。

下面是<span data-tone="red">运行渲染器</span>的命令。代码保留原来的空格与换行：

```bash
node scripts/render.mjs \
  --input "文章.md" \
  --out-dir "排版结果"
```

### 视频位置

视频会在原文位置保留一张占位卡。下面仅演示排版位置，发布前需要换成实际视频。

```wechat-video
title: 操作演示（占位示例）
source: 待上传：操作演示.mp4
```

| 元素 | 固定规则 |
| --- | --- |
| 正文 | 14px / 1.85 |
| 二级标题 | 18px / 700 |
| 图片 | 6px 圆角、细边框 |

> [!TIP] 复制前检查
> 预览页上的工具栏不会进入公众号正文。文章标题保存在单独文件里。

更多语法可以参考 [Markdown 指南](https://www.markdownguide.org/)。正文中的 `inline code` 也使用固定样式。

> [!END]
> 风格固定，表达留给作者。
