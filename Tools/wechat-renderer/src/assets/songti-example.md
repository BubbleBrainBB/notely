# 在工具之外，留一点自己的声音

我们每天打开很多窗口，接收很多消息，也学会了把越来越多的事情交给工具。可是，当一天结束，真正留在记忆里的，往往只是一个念头、一段对话，或一次意料之外的发现。

**有些文字，值得慢一点读。**

## 01 Notes · 写下结果与经过

第一次试用一个工具时，我们总想尽快知道它是否好用。于是截图、比较、记录，像整理一张清单。但一篇文章的意义，有时藏在清单之外。

你为什么开始尝试？哪一步让你犹豫？最后改变看法的，又是什么？这些细节，让同一件事有了不同作者的声音。

==把自己的判断写进去，记录才有了温度。==

### 给一个念头留出位置

这里的二级、三级标题采用宋体，正文保留系统字体。标题负责停顿，正文负责把故事继续说下去。这里特意把数字、英文与中文放在同一标题中，观察宋体的混排效果；编号和英文来自示例原文，不由模板自动添加。

> 我们记录一件事，不只是为了证明它发生过。
>
> 也是为了记住，那时的自己如何看待它。

引用向内收一些，用宋体和暖灰色拉开层次。它不需要边框，也不需要另一个底色。

## 02 Evidence · 让证据在场

技术文章里的截图，同样可以像刊物中的插图。保留原来的比例，在上下留出空间，用一行图注交代它是什么。

![一张图床截图，用来演示副刊中的图片与图注。](https://image-1325800846.cos.ap-nanjing.myqcloud.com/20260828134807607.png)

图片负责补充，文字负责解释。**普通加粗仍然是墨黑色**；只有你明确标记的 <span data-tone="red">胭脂红重点</span>，才会出现在段落中。

<u>一条浅色下划线</u>可以标出关键词，*灰色斜体*可以补上一句旁白。关于写法，可参考 [Markdown 指南](https://www.markdownguide.org/)。

### 旁注，而不是另一张卡片

> [!NOTE] 写在页边
> 有时，一句补充就足够。把它放在主叙述之外，但仍让读者看得见。

## 03 Steps · 留下可复现的路径

叙述可以慢，操作需要清楚。正文里的 `inline code` 使用系统字体和浅底色；完整命令则放在温暖的交通灯代码窗口里。

```bash
node scripts/render.mjs \
  --input "随笔.md" \
  --theme songti-supplement \
  --out-dir "副刊预览"
```

1. 先记录真实经历。
2. 再补充截图和操作步骤。
3. 最后检查，结论是否有足够的依据。

| 文字的角色 | 呈现方式 |
| --- | --- |
| 标题 | 宋体，二级标题胭脂红、三级标题墨色，充分留白 |
| 正文 | 系统字体、15px、舒缓行距 |
| 引用 | 宋体、暖灰、两侧缩进 |
| 强调 | 墨黑加粗，显式胭脂红点缀 |

<mark data-tone="warning">需要特别提醒时，仍可使用浅黄色标记。</mark> ~~不再采用的方案~~也可以留在记录中，说明思路如何变化。

## 04 Life · 文章之外，生活继续

不必为每一次体验写下宏大的结论。说清楚这次发现了什么，还有什么没想明白，就可以收笔。

> [!END]
> 工具帮助我们做得更多。文字提醒我们，为什么而做。
