# 蓝图档案：把一次尝试，留成一份记录

工具不断更新，值得留下的是我们如何观察、如何判断，以及最后发现了什么。

这是一份**蓝图档案**。白色留给阅读，墨黑组织信息，钴蓝标记值得停留的地方。让一篇技术文章，拥有清楚而稳定的节奏。

## 从一个具体的问题开始

好的记录不急着给出答案。先说明你想解决什么，再把尝试的过程展开。**短语加粗使用钴蓝**，而普通正文保持墨黑。

==真正值得保留的，是可以再次验证的发现。==

你也可以用 <u>细蓝下划线</u> 标记一个概念，用 *灰色斜体* 放下补充说明。它们都有固定的样式，但出现在哪里，由原文决定。

### 一段观察，一张证据

截图保持原来的比例，不加圆角和外框。图与图注靠近一些，与下一段留出距离，让读者知道它们属于同一个信息组。

## 把过程写得可以复现

正文中的 `inline code` 使用相同的系统字体，通过浅灰底区分。较长的操作放进交通灯代码窗口，浅灰蓝顶栏与浅色细边框保持统一，代码保留空格、缩进和换行。

```bash
node scripts/render.mjs \
  --input "文章.md" \
  --theme blueprint \
  --out-dir "蓝图预览"
```

1. 明确这次要验证的问题。
2. 记录输入、操作和观察结果。
   - 文字说明做了什么。
   - 截图补充看到了什么。
3. 回到问题，写下结论与局限。

> [!NOTE] 留下一条工作笔记
> 提示卡沿用浅蓝底与细蓝线，只展示你提供的标题和正文。

## 让不同信息各归其位

表格适合并排比较，引用适合补充视角，视频适合展示连续操作。选择最能说明问题的形式。

| 元素 | 蓝图档案的处理 |
| --- | --- |
| 正文 | 系统字体，15px，1.9 行高 |
| 章节标题 | 钴蓝编号、浅色竖线、墨黑标题 |
| 重点 | 钴蓝加粗、浅蓝高亮 |
| 截图 | 等比例、直角、无外框 |
| 代码 | 交通灯顶栏、浅灰底、浅色细边框 |

<mark data-tone="warning">提醒只在原文明确标记时出现。</mark> 显式指定的 <span data-tone="red">红色提示</span> 仍保留红色语义；~~不再采用的方案~~ 可以用删除线留作记录。

## 最后，回到你的发现

一篇记录不需要一个很重的结尾。说清楚这次学到了什么，下一次准备验证什么，就已经足够。
